DOCUMENTACIÓN DE ARQUITECTURA: DEMODULADOR SDR MODULAR
1. Visión General del Sistema

Este proyecto es una aplicación en Python con PyQt6 diseñada para interactuar con hardware de Radio Definida por Software (HackRF, RTL-SDR y Nuand bladeRF). Originalmente concebido como un script monolítico, el código fue refactorizado utilizando el Patrón Estrategia (Strategy Pattern) para separar estrictamente tres responsabilidades:

    La Interfaz Gráfica (UI) y Orquestación (main.py)

    El Control de Hardware y USB (hardware/)

    El Procesamiento Digital de Señales y Matemática (dsp/demodudores/)

Esta separación permite que se puedan agregar nuevos métodos de demodulación (AM, SSB, etc.) o nuevos equipos de radio sin alterar el núcleo de la aplicación.
2. Flujo de Datos (El camino de la muestra I/Q)

Para debugear, es vital entender cómo viaja la información desde la antena hasta la pantalla:

    Captura (Hardware): El equipo SDR captura señales RF. La librería de bajo nivel de cada equipo interrumpe por USB y envía bytes crudos.

    Normalización (Handler): Las clases en la carpeta hardware/ interceptan estos bytes crudos en hilos separados (o callbacks en C) y los convierten en un array de NumPy estandarizado de tipo np.complex128 (Muestras I/Q normalizadas).

    El Puente (main.py): El hardware llama al método procesar_muestras_iq(c_samples) de la ventana principal enviando este array.

    Matemática (Plugin DSP): El puente pasa el array de complex128 al método procesar() del demodulador activo (ej: WBFM o SA). El demodulador hace las FFTs, filtrados FIR, diezmados y cálculos de métricas.

    Retorno y Dibujo: El plugin DSP devuelve un diccionario unificado con datos listos para consumir (psd_rf, audio_out, etc.). El main.py agarra este diccionario, mete el audio en la cola y emite una señal de PyQt (emitter.data_updated) para que los gráficos se dibujen de forma segura en el hilo principal de la UI.

3. Descripción de los Módulos
A. Archivo Principal: main.py

    StartupWindow: Pantalla inicial. Se encarga únicamente de escanear los puertos USB (usb.core.find), identificar el VID/PID del hardware conectado e instanciar el Handler de hardware correspondiente.

    MainWindow: El controlador central. Solo maneja eventos de botones (callbacks) y dibuja trazados usando pyqtgraph. No hace ninguna operación matemática sobre las señales.

    Gestión de Audio: Utiliza sounddevice en un hilo secundario y una queue.Queue para amortiguar el audio entre los chunks de 100ms que escupe el DSP y lo que consume la placa de sonido de la PC.

B. Capa de Hardware (hardware/)

Abstrae las diferencias entre fabricantes. Todos los handlers heredan de SDRBase y exponen los mismos métodos (configurar, set_freq, set_sample_rate, start_rx).

    hackrf_handler.py: Usa pyhackrf. Convierte I/Q intercalados de 8 bits a complex128. Tiene un método exclusivo set_vga_gain que los otros equipos no tienen.

    rtlsdr_handler.py: Usa la lectura asincrónica nativa de rtlsdr en un hilo secundario (Daemon thread). Sus muestras ya vienen como complejos.

    bladerf_handler.py: Usa transferencias sincrónicas bloqueantes de alto rendimiento (sync_rx) configuradas en formato SC16_Q11. Corre dentro de un bucle while en un hilo (worker thread) propio para no congelar la UI de PyQt.

C. Capa de Plugins DSP (dsp/demoduladores/)

Todos los plugins heredan de DemoduladorBase. Tienen memoria propia (Z-states de filtros, buffers de acumulación), eliminando por completo la necesidad de variables globales en el programa principal.

    El Contrato: Todo plugin DEBE implementar un método procesar(muestras_iq) que retorne obligatoriamente un diccionario con llaves predefinidas (psd_rf, audio_out, metricas, etc.). Si una llave no aplica (ej: no hay audio), retorna None.

    sa.py (Spectrum Analyzer): El modo passthrough. Agarra las muestras crudas, saca el DC offset, calcula la FFT, la pasa a dB y retorna los vectores para graficar. No genera audio.

    wbfm.py (Wideband FM): El demodulador complejo. Acumula muestras hasta tener bloques de 100ms. Aplica filtros FIR (pasabajos y MPX), extrae el ángulo de la fase para demodular, calcula métricas de desviación (RMS, Pico a Pico) y normaliza el audio con de-énfasis para la tarjeta de sonido.

4. Gestión de Estado Global (state)

En main.py sobrevive un diccionario state muy reducido. Su único propósito es:

    Mantener parámetros que la UI necesita recordar (frecuencia actual, sample rate elegido).

    Servir como memoria compartida para el sistema de grabación cruda (interceptación de I/Q para guardar en archivos .npz).

    Sostener la cola de audio (audio_queue) y el flag de reproducción.
